WYSIWYG editor component

Question: ticket 02-wysiwyg-editor-component — pick Milkdown or Tiptap as Cerebrite's WYSIWYG editor, and decide whether Android ships WYSIWYG at MVP or falls back to plaintext. Clean markdown (ADR-0003) requires that saving never injects metadata outside YAML frontmatter — the right-hand panel below is the live markdown each editor would write to disk on save.
How to run this (desktop + Android)
  1. Desktop: just open this file directly in a browser (double-click, or file://…/02-wysiwyg-editor-component.prototype.html). No build step, no server needed.
  2. Android: file:// won't reach a phone. Serve this directory instead — from this folder run python3 -m http.server 8000 — then, from inside the sandbox, ask on the host: sbx ports <sandbox-name> --publish 8000:8000/tcp (substitute the sandbox's own name/IP). Open http://<sandbox-host-ip>:8000/02-wysiwyg-editor-component.prototype.html in Chrome on the Android device (same network as the host).
  3. Alternative if publishing ports is inconvenient: copy this .prototype.html file plus the two *.bundle.js files in 02-wysiwyg-editor-component.assets/ to any machine/phone you can serve statically from (a laptop's python3 -m http.server on the same Wi-Fi works fine).

What to react to

  

    Clean-markdown-out (can try right here, no Android needed):
    
    
      
  • Switch between scenarios (especially "Links & wikilinks") and compare the
        two editors' output panels. Tiptap's tiptap-markdown serializer
        backslash-escapes literal [[/]] brackets it doesn't recognize
        as its own syntax (\[\[…\]\]) — that's markup injected into the body that
        wasn't there on load, a real clean-markdown concern once Cerebrite adopts a
        wikilink-style syntax. Milkdown's commonmark serializer leaves them untouched.
    • 
      
  • Milkdown re-serializes bullets as * even if the source used -
        (and generally re-flows formatting more aggressively). ADR-0003 explicitly allows this —
        round-trip/diff fidelity isn't required — but confirm it doesn't bother you as a "my file
        churns every time I open it" experience.
    • 
      
  • Try pasting messy content (e.g. from a webpage) into each and check the output panel for
        stray HTML or attributes leaking through.
    • 
      
  • Look at the "Headings & inline formatting" scenario's output: Tiptap's
        tiptap-markdown serializer re-encodes the plain > character in
        "before a > blockquote below" as the HTML entity &gt; — a literal
        prose character turned into markup on save. Milkdown leaves it as a plain
        >.
    • 
    

    Android WebView behaviour (needs an actual Android device or emulator — this sandbox
      has neither):
    
    
      
  • Tap to place the cursor mid-word, then mid-list-item — is the tap target precise, or does
        it land in the wrong place?
    • 
      
  • Drag the selection handles to select a phrase spanning a bold/italic boundary.
    • 
      
  • Type a sentence using the on-screen keyboard's predictive-text / autocorrect — watch for
        broken IME composition (text appearing twice, cursor jumping, composed characters like
        accents or CJK input misplaced).
    • 
      
  • Press Enter inside a list item — does it continue the list correctly? Backspace at the
        start of a list item — does it outdent/exit the list the way you'd expect on mobile?
    • 
      
  • Rotate the device / resize the on-screen keyboard while focused — does the editor scroll
        correctly to keep the cursor visible?
    • 
      
  • If it's rough on either editor, that's the basis for Android falling back to
        plaintext-only at MVP; if it holds up, Android ships the same WYSIWYG UI as desktop.
