# Heading rename/move identity persisted via a git-synced redirect log

When a heading is renamed or moved ([ADR-0002](0002-linking-granularity-fixed-at-heading-level-for-mvp.md), [ADR-0005](0005-page-per-file-with-frontmatter-id-and-slug-addressed-headings.md)), a link addressing it by its old slug needs to keep resolving until every file that references it can be updated. The obvious approach — a redirect table living only in the in-memory [derived index](../../CONTEXT.md) — turns out to be unsound: the derived index is rebuilt from the markdown files alone and is never git-synced, so a redirect created on one device vanishes the moment the app restarts or another device pulls the rename, before the background cleanup job (which rewrites referencing files to the new heading directly) has had a chance to run. The link then breaks silently, with no trace left of the rename that caused it. A prototype (`.scratch/cerebrite-mvp/issues/04-stable-heading-identity.prototype.html`) confirmed the redirect-plus-cleanup-job mechanism itself works — it disambiguates slug collisions and collapses multi-hop rename chains correctly — but only once the redirect entries are made durable enough to outlive a single session.

The redirect table is therefore kept in its own small, git-synced, plaintext file, separate from the rest of the derived index, one entry per line so concurrent renames on different devices merge as ordinary non-conflicting line additions. This file carries no linkable content, so it isn't page content subject to clean markdown ([ADR-0003](0003-clean-markdown-excludes-round-trip-fidelity.md)) — it's the one deliberate exception to "the derived index is never git-synced." An entry is pruned once the cleanup job has rewritten every file that referenced the old heading identity; "temporary" describes that lifecycle, not an absence of persistence. Renaming the same heading on two devices before either syncs is still a genuine conflict, left to ordinary git conflict handling ([ADR-0006](0006-automatic-git-sync-with-conflict-detection-and-copy-safety-net.md)) rather than solved here. The exact file format, location, and pruning trigger are a separate, still-open question.
